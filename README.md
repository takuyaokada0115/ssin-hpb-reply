# SSIN STUDIO下北沢 — 店舗業務ツール

サロンの日常業務をClaudeで自動化する、2つのツールをまとめたNetlifyサイトです。
APIキーはNetlify Functions（サーバー側）にのみ保存し、ブラウザには露出しません。

| ツール | 画面 | 用途 |
|--------|------|------|
| HPB口コミ返信 自動生成 | `index.html` | 口コミを貼り付けると、熱量に合わせた返信コメントを作成 |
| スタッフ日報 自動生成 | `daily-report.html` | サロンボードの予約表から、スタッフごとの日報を作成 |

## ① HPB口コミ返信 自動生成ツール（`index.html`）

ホットペッパービューティー（HPB）の口コミを貼り付けると、投稿者のニックネームに対して、
口コミの熱量・感情に合わせた「お店からの返信コメント」を自動生成します。
スタッフは生成された文章をコピーして、HPBの返信欄に貼り付けるだけで完了します。

- 入力：口コミのテキスト貼り付け、またはスクリーンショット画像（ペースト／ドロップ／選択）
- 生成：Claude（Opus 4.8）が口コミを読み取り、熱量に応じてお礼／お詫びの返信を作成

## ② スタッフ日報 自動生成ツール（`daily-report.html`）

サロンボードの予約表（1日分）を貼り付けると、担当スタッフごとに分けた日報を作成します。
スタッフ本人へそのまま共有できる形になっているので、コピーしてLINE等に貼り付けるだけです。

### 入力のしかた（おすすめ順）

| 方法 | 手順 | 特徴 |
|------|------|------|
| **coming-soon画面＋通知メール（推奨）** | PCで予約管理画面を1枚スクショ＋その日の予約通知メールをテキスト欄に貼り付け | 担当者・顧客名は画面から、切れたメニュー名はメールから。**未割り当て予約も分かる** |
| coming-soon画面＋トラッキング表 | 予約管理画面のスクショ＋予約情報トラッキングの表をコピーして貼り付け | メニュー全文に加え、**ふりがなからカタカナ表記の顧客名**が作れる |
| coming-soon 予約管理画面のみ | その日のタイムテーブルをスクショ | 手軽。メニュー名は列幅で切れたまま |
| サロンボード CSV出力 | 予約一覧で「CSV出力」→ 中身をコピーしてテキスト欄に貼り付け | メニュー名が省略されない。ただし外部予約は顧客名が空 |
| サロンボード 予約一覧のスクショ | 予約一覧でスタッフを絞り込み → 検索 → スクショ | 手軽だが、外部予約の顧客名が出ずメニュー名も「…」で切れる |

- 画像は最大4枚まで（ペースト・ドロップ・選択）。縦に長い画面は分割して貼り付けられます
- 日付：空欄なら予約表から自動で読み取り。指定した場合はその日付を使用

### coming-soon 予約管理画面について

`1cs.jp` のタイムテーブル画面が、最も情報の揃った入力です。

- 左端の縦書き列が担当スタッフ、横軸が時刻
- **`FREE` 行は担当者が未割り当ての予約**。日報でも「FREE（未割り当て）」として、
  他のスタッフとは別枠（枠線を強調）で表示します。割り振ってから共有してください
- `BRK` は休憩、灰色の斜線セルは受付不可枠として、どちらも予約から除外します
- `HPB` `N` `i` `★` のアイコンは予約経路・顧客区分のマーカーとして無視します
- **PCなら1画面まるごとのスクショで構いません。** 横に広い画像は、送信前にブラウザ側で
  重なりを持たせて2〜3枚へ自動分割します。縮小による文字潰れを避けるためで、
  重複した時間帯の予約は1件にまとめられます（スマホで複数枚に分けて貼った場合も同じ）

サロンボードは、coming-soon経由の予約を「外部」と表示して顧客名を出しません。
この画面ならその制約がありません。

### 予約情報トラッキングの表による補完

coming-soonの「予約情報トラッキング」の検索結果は、テキストとして選択コピーできます。
これをテキスト欄に貼ると、予約管理画面では列幅で切れるメニュー名の全文と、
**顧客名のふりがな**が取れます。ふりがながある場合はカタカナ表記
（「水野愛弓(ミズノマナミ)」→「ミズノマナミ様」）で日報を作ります。

1件の予約が複数行に分かれた変更履歴なので、次のようにまとめてから使います。

- `外部システムの予約番号`（BF…）が同じ行を1件にまとめる
- `エラー原因` が入った行（`予約変更失敗` など）は反映されていないので無視する
- 担当スタッフは `予約登録日時` が最も新しい行の値を採用（`フリー` は未割り当て）
- メニューは同じ予約番号の行のうち最も詳しいものを採用（`予約` の行に正式名称が入る）
- `キャンセル` の予約は除外する

**注意：トラッキングの「期間」は施術日ではなく、予約を登録・変更した日です。**
9/9で検索しても返るのは「9/9に行われた予約操作」で、その施術日は9/21や9/26のこともあります。
そのため日報の主入力には使えません。対象日の `施術日時` を持つ行だけが日報に反映されます。
また、トラッキングデータは登録日から90日で削除されます。

### 予約通知メールによる補完

サロンボードは、coming-soon経由で入った予約を「外部」と表示し、**顧客名を出しません**。
メニュー名も一覧画面では「…」で切れます。この2つは、Gmailに届く
`【coming-soon】予約通知` のメール本文をテキスト欄に貼り付けると補完されます。

| 情報 | 正とする側 |
|------|-----------|
| 担当スタッフの割り当て | **予約表（スクリーンショット）のみ** |
| 顧客名（外部予約を含む）・メニュー全文 | 予約通知メール |
| キャンセル状態 | 両方（メールのキャンセル通知も反映） |

**担当者の判定にメールは使いません。** 予約は `[担当者] 指名なし` で入ってくることが多く、
その後の割り当て操作は通知メールを発生させないため、メールの `[担当者]` は実際の割り当てと
一致しないからです。

対応付けは、予約番号（`BF…`）が画面に見えていればそれを優先し、無ければ日付と開始時刻で
突き合わせます。同じ時刻の予約が複数あって特定できない場合は補完せず、「確認をおすすめする箇所」に
記載します。メールから補完した予約も同様に記載されるので、送信前に確認できます。

### 読み取りのルール

- **キャンセルは除外**します（お客様キャンセル／サロンキャンセル／無断キャンセル／自動キャンセル／お断り）。
  「受付待ち」「施術中」「済み」「会計済み」などは含めます
- **時刻の昇順に並べ替え**ます（予約一覧は新しい順に並んでいるため）
- **お客様名は予約表の表記のまま**です。予約一覧は漢字表記（「松山 奈央」→「松山奈央様」）、
  スケジュール画面やCSVのカナ列はカタカナ（「サクライキョウコ様」）になります。
  読みを推測して漢字をカタカナに変換することはしません（誤った読み仮名を防ぐため）
- **お名前が登録されていない予約**（予約経路「外部」など）は「10:00 外部予約」と出力します

### 出力

スタッフごとに以下の形式。文面はその場で編集してからコピーできます

```
ミサキ
9/6
10:00 サクライキョウコ様　まつぱ
11:00 ニシナアカリ様　眉ワックスまつぱ
12:30 タハラハルカ様　眉ワックス
```

- メニュー名は短縮表記に統一します（まつ毛パーマ→「まつぱ」、眉毛ワックス→「眉ワックス」、
  眉毛パーマ→「眉パーマ」、うなじシェービング→「うなじ」）。複数メニューは
  「眉ワックスまつぱ」のように連結します。
- 予約が0件のスタッフは「予約なし」と表示します。
- 読み取りに自信がない箇所は「確認をおすすめする箇所」としてまとめて表示されるので、
  送信前にその部分だけ確認してください。

### 読み取り精度・生成時間の調整

`netlify/functions/daily-report.js` の `output_config.effort` は `"medium"` です。
速度を優先したい場合は `"low"`、取りこぼしが目立つ場合は `"high"` に変更してください。

なお、Netlify Functionsには実行時間の上限（標準10秒）があります。予約表が大きく
タイムアウトする場合は、スクリーンショットをスタッフ数名ずつに分けて実行してください。

## 構成

```
index.html                        … 口コミ返信ツールの画面（静的・自己完結）
daily-report.html                 … スタッフ日報ツールの画面（静的・自己完結）
netlify/functions/generate.js     … 口コミ返信を生成する関数
netlify/functions/daily-report.js … 予約表を読み取り日報データを返す関数
netlify.toml                      … Netlify設定
package.json                      … 依存（@anthropic-ai/sdk）
```

## デプロイ手順（Netlify）

### 1. Anthropic APIキーを用意
[console.anthropic.com](https://console.anthropic.com) でAPIキー（`sk-ant-...`）を発行しておく。

### 2. Netlifyへデプロイ
どちらか片方でOK。

**A. Netlify CLIで公開**
```bash
cd ssin-hpb-reply
npm install
npx netlify deploy --prod
```

**B. GitHubリポジトリ連携**
1. このフォルダをGitHubリポジトリにpush
2. Netlifyの「Add new site」→「Import from Git」で連携
3. Publish directory は `.`、Functions は自動認識

### 3. 環境変数にAPIキーを設定（重要）
Netlifyのサイト設定 → **Site configuration → Environment variables** で以下を追加：

| Key | Value |
|-----|-------|
| `ANTHROPIC_API_KEY` | `sk-ant-...`（発行したキー） |

設定後、再デプロイすると反映されます。

## ローカルで動作確認

```bash
cd ssin-hpb-reply
npm install
export ANTHROPIC_API_KEY=sk-ant-...
npx netlify dev
```
表示されたローカルURLを開くと、関数込みで動作確認できます。
（`index.html`を直接ブラウザで開くと、関数が動かないため生成はできません）

## コストについて
口コミ返信は1件あたりおおよそ数円程度（Opus 4.8・画像あり時）。
日報は1日分（画像1〜4枚）でおおよそ十数円程度（Opus 5）。
コストを抑えたい場合は、各関数の `model` を
`claude-haiku-4-5`（安価・高速）や `claude-sonnet-5`（中間）に変更できます。
